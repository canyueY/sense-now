## 1. 当前仓库事实与兼容边界

当前版本：`0.0.5`，Node.js `>=20`，ESM。

现状：

- `src/capture.js` 是唯一启动 FFmpeg 的位置，只输出 `rgb24 rawvideo`，并通过 `-an` 丢弃音频。
- `src/pipeline.js` 是唯一视觉状态机：变化评分、切点、积分、留帧、档位、拼图、出图队列。
- `src/runner.js` 管采集进程、阻塞取图、文件结束、宽限期、挂断和悬浮窗。
- `src/index.js` 注册 DSH 工具并把 PNG 作为附件返回。
- `src/speech.js`/`src/voice.js` 是 AI 输出 TTS 事件总线，不是视频输入 ASR。
- 当前没有 Bilibili 接入、字幕获取、ASR、OCR、持久化索引、查询路由、人物跟踪或 Mnemosyne 客户端。
- 当前运行时除可选 peer dependency `@deepseek-ai/dsh-tools` 外没有 npm 依赖。
- 当前测试基线：85 项通过。

不可破坏的行为：

- `sense_now` 现有 action 和参数兼容。
- 文件源结束后不得自动从头重播。
- 用户关闭悬浮窗后不得自动重启。
- `say` 仍是悬浮窗可见、可听的唯一输出通道。
- 视觉队列深度、时序、编号、PNG 附件和 JSON 可序列化契约不变。
- 没有配置索引、Bilibili、ASR 或 OCR 时，原插件应与修改前一致。

## 2. V1.1 目标与非目标

### 2.1 目标

将系统从“每次让模型重新理解视频”升级为：

```text
视频输入
  → 本地感知与证据保存
  → 建立分层可检索索引
  → 用户提出问题
  → 查询路由与相关性检索
  → 按需读取文本、关键帧或局部证据
  → Token/Cognition Gate
  → DSH 在窄上下文中回答
```

要求达到：

- 一次索引，多次查询。
- 文本优先，视觉按需。
- 摘要可回溯到原始字幕、ASR、事件、帧或音频时间段。
- 默认静默建索引，不因普通章节、字幕、帧或人物事件自动唤醒模型。
- 人物贴图与音色绑定作为索引能力之一，而不是整个系统的前置条件。
- 用户明确要求时，才能把选定知识和证据交给 Mnemosyne。

### 2.2 非目标

- 不在 V1.1 内训练自有 ASR、OCR、人脸或主动说话人模型。
- 不绕过 Bilibili 登录、付费、地域、版权、DRM 或访问控制。
- 不把摘要当作唯一事实存储。
- 不默认把整个视频、完整 Evidence Package 或生物特征写入长期记忆。
- 不把“全片只有一个音色”直接断言为 UP 主本人，只能标记为疑似主讲人/旁白，除非有额外证据或用户确认。

## 3. 必须冻结的架构决策

实现必须遵守 D13–D23：

- **D13 索引优先**：首次处理建立可检索索引，后续查询不重新摄入整部视频。
- **D14 推理与感知解耦**：本地感知负责产出结构化证据，大模型只回答具体问题。
- **D15 视觉按需获取**：默认先查文本；视觉问题先读已有 Storyboard，证据不足才局部 zoom。
- **D16 本地视觉门控**：帧进入 DSH 上下文前先完成低成本筛选、去重和 ROI 处理。
- **D17 Cognition Gate**：章节完成、普通 ASR、场景变化不自动触发大模型。
- **D18 双级证据包**：Minimal Index 默认生成，Full Evidence 按需展开。
- **D19 动态模块调度**：按内容与查询需要启用 OCR、diarization、人物和主动说话人模块。
- **D20 分层索引表示**：摘要与细节分开保存，但保持稳定引用。
- **D21 查询缓存**：同一索引版本和证据集合可复用检索与局部分析结果。
- **D22 硬预算控制**：检索、文本、视觉预算由代码强制执行，不只写在提示词里。
- **D23 Mnemosyne 按需接入**：只提交用户选择的知识及其相关证据。

## 5. 索引存储布局

默认根目录：

```text
${DSH_HOME}/sense-now/video-index/
```

若没有 `DSH_HOME`，沿用项目现有 home 解析习惯。测试必须注入临时目录，禁止写真实用户索引。

单视频目录：

```text
video-index/<videoKey>/
  manifest.json
  metadata.json
  summary/
    chapters.json
    topics.json
    entity-overview.json
    key-moments.json
  detail/
    timeline.json
    utterances.json
    events.json
    subtitles.json
    entity-tracks.json
  evidence/
    evidence-index.json
    storyboard-index.json
    audio-index.json
    frames/
    audio/
  cache/
    queries.json
```

要求：

- 所有 JSON 使用 UTF-8。
- 写入采用“同目录临时文件 + rename”的原子替换。
- `manifest.json` 最后写；它代表一次索引提交完成。
- 崩溃留下的临时文件不能被当成有效索引。
- 删除索引只删除已解析且位于索引根目录内部的目标 `videoKey`，必须防路径穿越。
- 不默认复制原始视频；只记录受控 source reference。若缓存媒体，必须由显式配置控制。

## 6. 统一 Schema

### 6.1 Manifest

```json
{
  "schemaVersion": "1.1",
  "indexVersion": "content-hash-or-monotonic-version",
  "videoKey": "bilibili:BVxxxx:p1",
  "source": {
    "kind": "bilibili",
    "uri": "https://www.bilibili.com/video/BVxxxx",
    "partId": "p1"
  },
  "status": "ready",
  "createdAt": "ISO-8601",
  "updatedAt": "ISO-8601",
  "capabilities": {
    "metadata": "ready",
    "subtitles": "ready",
    "storyboard": "ready",
    "asr": "unavailable",
    "ocr": "unavailable",
    "diarization": "unavailable",
    "identityBinding": "unavailable"
  },
  "versions": {
    "pipeline": "0.0.5+",
    "retrieval": "1",
    "adapters": {}
  },
  "counts": {
    "chapters": 0,
    "events": 0,
    "utterances": 0,
    "storyboardUnits": 0,
    "evidence": 0
  }
}
```

`status` 只能为 `building | ready | degraded | failed`。单个能力失败应优先得到 `degraded`，不要让已有字幕或 Storyboard 一起失效。

### 6.2 EvidenceRef

所有摘要和事件必须通过统一引用回到证据：

```json
{
  "evidenceId": "EVID_...",
  "kind": "subtitle|asr|frame|audio|event|metadata",
  "startMs": 12400,
  "endMs": 15800,
  "ref": "evidence://<videoKey>/frame/FRAME_001",
  "sourceFile": "evidence/frames/FRAME_001.png",
  "contentHash": "sha256:...",
  "provenance": {
    "adapter": "storyboard-indexer",
    "version": "1",
    "generatedAt": "ISO-8601"
  }
}
```

`ref` 是逻辑引用，不能把任意用户路径直接暴露给模型。`sourceFile` 必须解析在当前视频索引目录内。

### 6.3 StoryboardUnit

```json
{
  "frameId": "FRAME_001",
  "timestampMs": 12400,
  "imageRef": "evidence://<videoKey>/frame/FRAME_001",
  "sceneId": "SCENE_001",
  "sourceSize": { "width": 1920, "height": 1080 },
  "storedSize": { "width": 800, "height": 450 },
  "roi": { "x": 120, "y": 80, "width": 640, "height": 360 },
  "transform": {
    "scaleX": 0.4166667,
    "scaleY": 0.4166667,
    "offsetX": 0,
    "offsetY": 0
  },
  "selectionReasons": ["scene_change", "subtitle_change"],
  "evidenceIds": ["EVID_..."]
}
```

ROI 坐标以原始画面为准。若没有裁剪，则 ROI 为完整原始画面。禁止只保存裁剪后坐标而丢失原始映射。

### 6.4 Chapter 与摘要溯源

```json
{
  "chapterId": "CH_001",
  "title": "介绍核心概念",
  "startMs": 0,
  "endMs": 85000,
  "summary": "介绍系统的基本原理",
  "topicTags": ["系统设计", "记忆架构"],
  "eventIds": ["EVENT_001"],
  "evidenceIds": ["EVID_001", "EVID_002"],
  "summaryMethod": "subtitle-rules|asr-rules|external-model",
  "confidence": 0.8
}
```

规则生成不了可靠摘要时，允许标题或摘要为空，但不能发明内容。不得渲染“TODO”或伪摘要。

### 6.5 人物与音色

```json
{
  "personId": "P1",
  "faceTrackIds": ["FACE_03"],
  "speakerClusterIds": ["SPEAKER_01"],
  "avatarRef": "evidence://<videoKey>/frame/FACE_P1_BEST",
  "bindingState": "unbound|tentative|confirmed|conflict",
  "confidence": 0.93,
  "evidenceIds": ["EVID_SOLO_01", "EVID_SYNC_02"],
  "label": "疑似主讲人",
  "labelSource": "inference|metadata|self-introduction|user-confirmed"
}
```

脸向量、声纹向量不得放进给大模型的上下文。默认仅会话或本地索引内保存；长期持久化必须有显式配置。

## 7. 稳定 ID 规则

在 `ids.js` 中集中实现，禁止各模块自行拼 ID。

要求：

- `videoKey`：规范化 source kind、平台 ID、分 P。
- `frameId`：由 `videoKey + timestampMs + roi + contentHash` 决定。
- `evidenceId`：由 `videoKey + kind + startMs + endMs + contentHash` 决定。
- `chapterId`/`eventId`：同一索引版本内稳定。
- 使用 Node 内置 `crypto.createHash('sha256')`，输出短前缀时保留足够长度并测试碰撞行为。
- 同一输入重复索引应产生相同证据 ID；内容改变必须导致 `indexVersion` 改变。

## 8. 核心 API 契约

### 8.1 VideoIndexEngine

```js
createVideoIndexEngine({
  rootDir,
  ffmpegPath,
  adapters,
  clock,
  log,
})
```

返回：

```js
{
  index(input, options),
  query(request),
  getEvidence(request),
  status(videoKey),
  list(),
  remove(videoKey),
  close()
}
```

所有长任务接收 `AbortSignal`。取消后不得提交 `ready` manifest。

### 8.2 index(input, options)

输入：

```js
{
  source: { kind: "file", path: "D:/video.mp4" }
  // 或 { kind: "bilibili", url: "...", partId: "p1" }
}
```

options：

```js
{
  profile: "auto|tutorial|interview|game|anime|vtuber|documentary|music",
  capabilities: {
    subtitles: "auto|on|off",
    asr: "auto|on|off",
    ocr: "auto|on|off",
    diarization: "auto|on|off",
    identityBinding: "auto|on|off"
  },
  rebuild: false,
  signal
}
```

相同 source fingerprint 且索引 `ready` 时默认复用；`rebuild:true` 才重建。

### 8.3 query(request)

```js
{
  videoKey,
  question,
  mode: "auto|text|time|visual|multimodal|deep",
  budget: {},
  signal
}
```

返回检索结果而不是伪造最终答案：

```js
{
  queryType,
  decision: "local|llm|deferred|insufficient",
  reasons: [],
  context: {
    metadata: {},
    chapters: [],
    events: [],
    utterances: []
  },
  visualEvidence: [],
  citations: [],
  budget: {
    requested: {},
    used: {},
    estimated: true,
    truncated: false,
    omittedEvidenceIds: []
  },
  cache: { hit: false, key: "..." }
}
```

DSH 模型根据这个工具结果回答用户。索引层本身不得编造自然语言结论。

## 9. 查询路由

`query-router.js` 必须先使用确定性、可解释规则，返回类型与命中理由：

- `text_structure`：讲了什么、总结、主题、章节。
- `time_locator`：什么时候、哪一段、首次出现、前后内容。
- `visual`：界面、颜色、人物外观、软件、按钮、画面内容。
- `multimodal`：某人说话与操作关系、音画矛盾、人物与音色。
- `deep`：用户明确要求深度分析、论证、比较、复核。

规则要求：

- 显式 `mode` 优先。
- 时间词不自动意味着视觉。
- “视频讲了什么”默认只取 L0/L1。
- “画面里是什么”必须进入视觉路由。
- 规则不确定时可选 `multimodal`，但要受预算约束。
- 输出 `reasons`，例如 `['contains_visual_terms', 'explicit_timestamp']`。

不要为了路由再默认调用一个模型。

## 10. 检索与上下文构建

### 10.1 检索优先级

1. 元数据精确匹配。
2. 章节标题和主题标签。
3. 事件、字幕、ASR 文本相关性。
4. 时间邻近和章节范围。
5. 视觉 Storyboard 引用。
6. 局部 zoom，仅在已有关键帧不足时。

初版可以使用无依赖的本地检索：

- Unicode 归一化和中文/英文 token 化。
- 精确短语、关键词覆盖、时间范围、字段权重。
- 可解释分数明细。

不要引入不可验证的“向量检索”占位实现。后续可通过 adapter 增加 embedding 检索。

### 10.2 Context Builder

按以下顺序保留证据：

1. 与问题直接相关的证据。
2. 冲突证据和关键反例。
3. 必要前后文。
4. 章节摘要。
5. 低相关细节。

超过预算时：

- 低相关细节可降级为摘要。
- 关键证据不得静默截断。
- 返回 `omittedEvidenceIds` 和 `truncated:true`。
- 若删减后无法可靠回答，返回 `decision:'insufficient'`，不要假装完整。

## 11. Token Gate 与视觉硬预算

默认预算：

```json
{
  "maxChapters": 3,
  "maxEvents": 12,
  "maxUtterances": 20,
  "maxTextTokens": 6000,
  "maxStoryboardUnits": 4,
  "maxSingleFrames": 2,
  "maxZoomRequests": 2,
  "maxVisualTokens": 8000
}
```

这些只是配置默认值，不是性能承诺。

要求：

- 真实 tokenizer 可用时使用真实值，并记录 `estimated:false`。
- 没有 tokenizer 时使用保守估算，必须标记 `estimated:true`。
- 不能把字符估算标成精确硬上限。
- 视觉模型没有 Token 计量时，根据像素、图片数和已知模型限制估算。
- 三层预算分别统计：retrieval、text、visual。
- Gate 在构造附件前执行；不能图片已经保存到 DSH 后才发现超预算。

## 12. Cognition Gate 与沉默机制

`cognition-gate.js` 输出：

```js
{
  state: "candidate|ready|deferred|skipped",
  decision: "local|llm|queue",
  reasons: [],
  requiredEvidenceIds: []
}
```

默认不调用/不唤醒模型：

- 章节完成。
- 新增普通 ASR。
- 普通场景切换。
- 新增字幕。
- 检测到新人物但用户没有询问。

允许进入模型上下文：

- 用户正在提问。
- 用户明确要求总结、解释、比较或深度分析。
- 索引无法回答且存在必要证据。
- 用户要求复核冲突或人物身份。

高价值知识片段只能标记 `candidate`，不能因此自动触发 DSH。

现有实时 `loop.js` 行为只服务 `sense_now` 实时陪看，不要把离线索引事件接入该自动唤醒循环。

## 13. Storyboard 与本地门控

### 13.1 保留并扩展现有 pipeline

不要推翻 `cuts.js`、`pipeline.js`、`tiers.js`、`pack.js`、`sheet.js`。它们已经通过大量视觉回归测试。

推荐接入方式：

- 在 `createPipeline` 增加可选、默认关闭的事件回调或 observer。
- 留帧时发出不可变元数据事件：时间、via、score、tier、selectionReasons。
- `storyboard-indexer` 订阅并保存单帧证据及 sheet→frame 映射。
- 未传 observer 时行为和性能尽量保持原样。

禁止让 `pipeline.js` 直接写文件或知道索引目录。

### 13.2 Frame Gate 信号

统一信号：

- `frame_difference`
- `scene_boundary`
- `duplicate_rejected`
- `subtitle_change`
- `audio_event`
- `ocr_change`
- `entity_change`
- `manual_request`

P1 必须真实实现现有视觉变化、场景/积分和字幕变化信号。OCR、音频和实体信号只有在对应 adapter 可用时启用；不可用时不伪造。

### 13.3 Zoom

新增局部证据获取接口，但必须满足：

- 只能针对已索引视频和明确时间段。
- 先检查已有 Storyboard 是否足够。
- 每个查询受 `maxZoomRequests` 限制。
- zoom 结果写入证据索引并可缓存。
- ROI 保留原始坐标与变换。
- 禁止因普通问题重新扫描整部视频。

## 14. Bilibili Source Adapter

实现 `bilibili-source.js`，但不要把平台逻辑散落在索引引擎中。

建议使用可配置的 `yt-dlp` CLI 适配器：

- 路径优先级：显式参数 → `DSH_YTDLP_PATH` → PATH 中的 `yt-dlp`。
- 使用参数数组调用 `spawn`/`execFile`，禁止拼接 shell 命令。
- 元数据使用 JSON 输出解析。
- 优先获取平台字幕；视频下载只在用户显式执行 index 且需要 Storyboard/音频时发生。
- cookies 只能使用用户显式配置，不读取或上传未授权数据。
- 不绕过 DRM、登录、付费或地域限制。
- 缺少 `yt-dlp` 时返回可操作错误，不影响本地 file source。
- 测试使用 fake executable 或注入 runner，禁止测试访问真实 Bilibili 网络。

Source adapter 统一返回：

```js
{
  videoKey,
  metadata,
  parts,
  subtitles,
  mediaRef,
  fingerprint,
  provenance
}
```

## 15. ASR、OCR、说话人和人物适配器

外部感知能力必须通过 adapter 接口，不与索引核心绑定具体模型。

最低接口：

```js
{
  name,
  version,
  available(),
  analyze(input, { signal, onProgress })
}
```

行为规则：

- 字幕优先：平台字幕可用时，默认不重复跑 ASR。
- 用户显式要求复核或字幕缺失时才启用 ASR。
- 教程/科普默认不运行 diarization；检测到多人对话或用户询问人物时再启用。
- 人物识别不是 V1.1 查询可用性的前置条件。
- adapter 不可用时在 manifest capabilities 中记录 `unavailable` 和原因。
- adapter 运行失败时保留其他能力，索引可为 `degraded`。
- 不允许把模型输出直接视为事实；保留模型名、版本、置信度和证据引用。

若仓库没有可合法分发的模型，不要偷偷增加数 GB 下载。可实现“外部命令 JSON 协议适配器”，但必须有真实协议、输入校验、超时、取消、输出 schema 校验和 fake-command 集成测试；不能只留一个永远返回空数组的类。

## 16. 人物贴图与音色绑定（P4）

### 16.1 四步证据流程

1. **开头候选**：检测出现人物和音色簇，按可见时间、嘴部活动和同期语音生成 tentative 候选。
2. **单人确认**：优先寻找“单人可见 + 嘴动 + 清晰非重叠语音”的片段；多个独立片段稳定一致后才 confirmed。
3. **组合纠错**：利用 `A → A+B → B`、`A+B → B+C → A+C` 等人物集合变化纠正绑定。
4. **无人回退**：无人画面继续 ASR/diarization；单一音色标“疑似主讲人/旁白”，多音色匿名留白，后续证据出现再回溯。

### 16.2 绑定状态

- `unbound`
- `tentative`
- `confirmed`
- `conflict`

确认不能只靠单个固定分数。最低要求：多个独立证据、足够清晰语音、无强冲突。阈值配置化并通过测试样本标定。

### 16.3 特殊场景

- 单人出镜但旁白说话：保持 audio-only。
- 两人同时说话：保留 overlap，不压成单人。
- 配音、电视、口型不一致：降低置信度或不绑定。
- 人物离场再出现：脸和声纹双证据；冲突时不自动合并。
- 全片单音色：不得直接写“UP 主本人”。

## 18. 工具层设计

保留现有 `sense_now` 工具，新注册一个职责独立的 `video_index` 工具。不要把十余种离线动作继续塞进 `sense_now`。

`video_index` actions：

- `index`
- `query`
- `evidence`
- `zoom`
- `status`
- `list`
- `remove`

参数至少包括：

```js
{
  action,
  source,
  path,
  url,
  partId,
  videoKey,
  question,
  mode,
  profile,
  budget,
  evidenceIds,
  startMs,
  endMs,
  roi,
  rebuild
}
```

工具约束：

- `index` 和 `remove` 是明确写操作；错误信息必须写清影响范围。
- `query` 默认只返回文本和引用；只有路由需要视觉时才附图片。
- `evidence` 只允许读取属于目标索引的受控引用。
- `zoom` 强制预算和范围。
- `remove` 必须精确删除一个 `videoKey`，不得递归删除索引根目录。
- 所有返回值可无损 JSON 序列化，不含 `undefined`、Buffer 或循环对象。
- 更新 `test/plugin.test.mjs`：验证同时注册 `sense_now` 与 `video_index`，并在 dispose 时都解绑；不要删除对 `sense_now` 的检查。

## 19. Minimal 与 Full Evidence Package

### 19.1 Minimal Index Package

默认生成，包含：

- 元数据与分 P。
- 章节骨架、主题标签和关键时间锚点。
- 核心实体匿名 ID。
- 重要事件摘要。
- Storyboard 引用。
- 证据索引引用。
- schema、索引、算法和适配器版本。

它是本地可检索资源，不应每轮完整塞入上下文。

### 19.2 Full Evidence Package

仅在用户明确请求深度分析、复核、保存知识或审计冲突时按范围生成：

- 指定范围的完整字幕/ASR。
- 详细事件和时间轴。
- 相关关键帧、ROI、音频片段。
- 人物绑定证据。
- 模型和算法版本。
- 候选知识及来源。

不得因为用户只问一个知识点就展开整部视频。

### P0：Schema、时间轴、索引存储、预算

- 普通索引事件不唤醒模型。

- 不配置 Mnemosyne 时无副作用。

## 24. 安全、隐私和失败策略

- 所有外部命令使用参数数组，禁止 shell 字符串拼接。
- 用户 URL、路径、字幕、模型输出均为不可信输入。
- 限制单文件大小、JSON 深度、数组长度和文本长度。
- 子进程支持超时、取消和强制清理。
- 索引引用必须限制在视频目录内。
- 不把 cookies、token、绝对私人路径或原始声纹/脸向量送入 DSH 上下文。
- 脸向量和声纹属于生物特征；默认本地、会话级或显式启用持久化。
- `remove` 后报告删除的精确 videoKey 和是否可恢复。
- 某能力失败时优先降级，不让整个索引不可用。

## 一句话开发基线

**先把视频变成可寻址、可复用、可追溯的本地索引；再根据用户问题，在硬预算内装载最少但充分的文本与视觉证据。**
