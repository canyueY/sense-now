# 调参与实测

这份文档只解决一个问题：**AI 说的和你想的不一样时，该拧哪个旋钮，拧到多少。**

---

## 一、先分清"漏了"还是"太密"

| 症状 | 真正的原因 | 该动的旋钮 |
|---|---|---|
| 换了一屏，它没反应 | 这一下的分数没过切点门槛 | `pace` → `dense`（或降 `cutAbs`） |
| 一直在动，它一句话不说 | 积分还没攒够，或者被唤醒节流吞了 | `pace` → `dense`（缩短叫醒间隔） |
| 它一直在说话，很吵 | 留帧太多 + 唤醒太频繁 | `pace` → `calm` |
| 说了一堆，但没说出重点 | 这不是参数问题，是模型选择问题 | 用 `say` 的措辞要求它"一句话" |
| 它说"没变"，其实变了 | 变化在画面里占比太小（比如只改了一个小图标） | 换不到旋钮 —— 见"能力边界" |

**最快的诊断方式是打开调试窗，读那根柱子的高度。**

```bash
npm run debug:live                      # Windows 双击 debug/调试窗.cmd 也行
```

窗口上方第一条曲线是**每帧变化分**，虚线是参考强度 4。换画面的那一瞬间：

- **一根高柱，前后贴地** → 这是硬切，只要柱高超过门槛就会留下（见下表）
- **连着几根中等高度** → 这是渐变/滚动，走的是积分那条路，靠"攒够量"
- **全程贴地** → 画面真的没变

帧流左边那些琥珀色加粗的行，是**过了七成门槛但没过线**的帧 —— 调 `cutAbs` 的时候看它们落在多少分，比看曲线估要准得多。

## 二、`cutAbs` 到底该给多少（实测矩阵）

同一套代码，12fps，每张画面停 2 秒：

| 素材 | 换画面那一帧的分 | 25 | 15 | 12 | 7 |
|---|---|---|---|---|---|
| 差异明显的照片 | 46.6~63.4 | 5 | 5 | **5** | 5 |
| 色调接近的照片 | 16.0~17.9 | 0 | 5 | **5** | 5 |
| 极相似（裁切差 8px） | 7.3~8.2 | 0 | 0 | **0** | 5 |
| 只改亮度 | 5.3 | 0 | 0 | 0 | 2 |
| 连续运动（合成片） | 峰值 11.7 / 中位 3.7 | 0 | 0 | **0** | 0 |
| 缓慢放大 | 峰值 13.6 | 0 | 2 | **0~2** | 2 |
| 滚动网页 | 30~42 | 5 | 5 | **5** | 5 |
| 光标在静止画面移动 | 峰值 **0.7** | 0 | 0 | **0** | 0 |

（"该有几刀"= 6。表里是实际命中数。）

**读法：**

- `25` 只能抓"两张完全不同的照片"，色调接近就全漏
- `12`（默认）是**照片切换抓得住、日常操作不碎**的平衡点
- `7` 能连"极相似"也抓住，但代价是日常屏幕上的小突变也会留帧 —— 所以它被做成了 `pace:"dense"`，而非常量默认
- `5` 及以下没有意义：只多认出"只改亮度"这种肉眼都看不出的变化

## 三、为什么不能把绝对门槛去掉，只用"尖峰"

因为**尖峰是相对判据**，在低分区同样成立。

实测缓慢放大那段，有两帧是这样的：

```
s = 13.6   前 = 1.1   后 = 1.3
尖峰门槛 = 2.5 × max(1, 1.1, 1.3) = 3.3
13.6 > 3.3  →  尖峰判据完全放行
```

也就是说，只有尖峰没有地板的话，**持续运动会被切成一块块**。
反过来只有地板也不行：一镜到底的视频每帧 4 分，永远不会"跳"，只能靠积分。

**地板管"变化够不够大"，尖峰管"是不是一下子"。两个都要。**

## 四、积分阈值（`integralSeconds`）

```
need = 参考强度(4) × fps(12) × integralSeconds(3) = 144
```

它的语义是：**一段"中等强度"的画面，攒够 3 秒才该出一个采样点。**

关键：阈值是**固定的绝对值**，绝不跟着画面一起涨。早先版本用过"阈值 ∝ 当前平均变化量"，结果画面动得越快阈值越高，退化成"固定 N 秒一帧"—— 那个实现被删了。

**代价**：对幻灯片不友好。换一张照片只在那一瞬间贡献 17 分（后面 23 帧是 0），要换 8~9 张才攒够 144。
这就是为什么幻灯片必须靠切点判据，而不能指望积分。

改它的影响（合成片 24 秒）：

| `integralSeconds` | 留帧 |
|---|---|
| 3（默认） | 7 |
| 1.5 | 12 |

**帧数几乎翻倍**，别为了"更灵敏"随手改它 —— 先动 `pace`。

## 五、档位（`dtFrames`）—— 它不参与判定

`dtFrames` 只决定**格子多大**，跟"该不该留这一帧"无关。

档位 k 的含义是格子边长 1/k，一张图最多 k² 格。它是按"最近 1 秒留了几帧"算的：

| 节奏 | 1 秒窗（默认 dtFrames=12） | 2 秒窗（dtFrames=24） |
|---|---|---|
| 每 2 秒换一张照片 | 档位恒 1 → 一张图 3 张照片 | 档位 2 → 一张图 4 张照片 |

**逐场景模式**（`scene:true`）把这层直接绕过了：档位固定压到 1，一帧铺满整张图。

## 六、处方速查

| 你想要 | 怎么做 |
|---|---|
| 省钱、少说话 | `pace:"calm"` |
| 默认手感 | `pace:"normal"` |
| 抓极相似的照片切换 | `pace:"dense"` 或 `scene:true` |
| 每个画面单独一张满幅图 | `scene:true` |
| 读清楚屏幕上的小字 | `quality:"high"`（会重启采集，但立刻给一帧） |
| 只看这次，别唤醒 | `action:"peek"`（不阻塞、不叫醒） |

## 七、能力边界（这些不是参数能解决的）

- **小面积变化**：一个图标变了、一个字改了，分数可能只有 0.5~2。地板调到能抓住它的时候，噪音也会一起进来。
- **语义没变但画变了**：同一句话换了个排版，分数很高，会被当成"换画面"。
- **跨帧去重是粗筛**：`dupMin`（默认 8）只跟"上一张留下来的帧"比，不跟整个历史比。
