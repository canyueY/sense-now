## 4. 发现的问题

### P1 `query` 的文本通道没有证据正文

`src/video-index-tool.js:345-357` 里模型可见的 `text` 只有四行计数：

```
queryType=text_structure decision=llm
reasons: ...
chapters=1 events=12 utterances=20
visual=0 cacheHit=no
```

utterance 正文、时间戳、`evidenceId` 全在 `meta` 里，而模型读不到 `meta`。结果是：
问“这条视频讲了什么”，Agent 只拿到“有 20 条 utterance”，**没有任何可引用的台词**，
与 README“query 返回的是可供 Agent 回答的证据与引用”不符。建议把 top-N utterance
（`[mm:ss] 文本 (EVID_xxx)`）直接拼进 `text`。

### P2 chunk 布局的 storyboard 是“假 ready”

`chunks/000000/storyboard.json` 里的四个单元只有 `frameId / timestampMs / chunkId`，
没有 `imageRef`、`evidenceIds`，`evidence/frames/` 下也没有对应 PNG；
但 `chunk-manifest.json` 写的是 `storyboard: "ready"`。后果：
`query(mode:visual)` 返回 `visual=0` + `storyboard_insufficient_zoom`，图像永远取不到。
与 README“未验证的 adapter 不写假 ready”冲突。

（另注：本轮这块视频轨道本身是纯黑——我用裸 `ffmpeg` 在 1.65 s / 201.5 s / 331.5 s 和
全解码到 200 s 各取一帧，字节完全相同，确认是素材问题，不是 zoom 的 seek bug。
但“storyboard 单元没有图像引用”是代码问题，与素材无关。）

### P3 monolithic 布局的 coverage 全零

`file=0eda4c69ce8f=.../analysis/coverage.json`：

```json
{ "durationMs": 0, "textRanges": [], "coverageRatio": 0, "status": "poor" }
```

而 manifest 里 `counts.utterances = 109`、时长 450.97 s。字幕优先路径没有把文本范围写进
coverage，于是“全片都索引过”的视频被标成 `poor / 0`——按 Agent 协议第 5 条，模型会据此
说“证据不足”。chunk 布局则完全没有 coverage.json。

### P4 `.building.json` 残留

monolithic 建索引成功后，索引目录里仍留着 `.building.json`，内容为 `status: "building"`、
`counts` 全 0。原子发布应该清掉这个 marker，否则崩溃恢复逻辑会看到“正在构建”的陈旧状态。

### 其他小项

- `analysisPolicy:{}` 下 monolithic 与 chunk 两条路径的 capabilities 不一致（前者 `storyboard=skipped`，后者 `ready`），排查时容易误判。
- 内嵌字幕轨与外部 SRT 都能正常接管，但本轮 .mkv 的字幕覆盖率只有 0.957 / 0.935，`textConfidence=0`，建议对字幕置信度补一个可解释的取值。
