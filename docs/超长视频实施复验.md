## 2. 关键发现（按严重度）

### 🔴 C1. 抓播主路径没有真正采集

三条独立证据：

1. **没有 tick 循环**：`capture-source.js` 定义了 `tick()`，但全仓库没有任何地方调用 `session.tick()`。CDP 的 `currentTime/paused` 永远不会被采样，时间轴不会更新。
2. **没有 recorder 适配器**：引擎只有 `recorder: adapters.loopbackRecorder || null`（`video-index-engine.js:1172`），全仓库没有 `createLoopbackRecorder` 或 spawn `scripts/loopback-recorder.py` 的 Node 适配器。默认 `capture_start` 不录任何音频。
3. **没有帧采集**：`createCaptureSession` 只对接 recorder + CDP，没有调用 `capture.js` 的 `spawnFrames`。抓播不会产生任何画面。
4. **capture job 不产 chunk**：`captureStart` 只是 `jobs.createJob({state:'capturing'})`，`captureStop` 只把状态改成 ready/degraded；`runIndexingJob` 只服务于 `startIndexJob`，capture job 没有索引分支。

后果：`capture_start` 返回 `ok`，但**没有音频、没有画面、没有 chunk**；用户会以为在抓，实际空转。
（新增检查 H4/H5/H6 全 fail，已列入 gap L5/L6/L7。）

### 🔴 C2. 跨块 speaker 合并没有生产端

- 引擎固定传 `returnEmbeddings: false`（`video-index-engine.js:251`），没有任何开关；
- Python runner 收到 `returnEmbeddings` 后只是 `pass`（`audio-visual-runner.py:125-127`），实测 `returnEmbeddings:true` 输出仍是 `speakers/activeSegments/overlaps/observations`，**没有 `speakerEmbeddings`**；
- `mergeSpeakersByEmbedding` 只有单测，没有被引擎调用。

后果：所有跨块 speaker 都是 `Cxxxxx_SPEAKER_yy` provisional，**永远不会合并成全局人物**。计划里“embedding 合并”目前只是函数，不是链路。

### 🟠 C3. cancel 不是终态（竞态）

实测：

```
cancel returned: true state: cancelled
final state: ready | chunks committed: 1
```

`jobCancel` 立刻写 `cancelled`，但在跑的 `indexChunk` 不检查 abort，完成后仍 `commitChunk` 并把 job 覆盖成 `ready`。
后果：用户取消后仍会写入一块，状态也骗人。

### 🟠 C4. `job_status/job_cancel/job_resume` 对非法 jobId 直接抛错

`job-store.js:47` 对 jobId 做正则校验并抛 `unsafe jobId`；工具层没有捕获（`video-index-tool.js:512-540`）。
模型只要传一个不存在的 id（如 `nope`），工具调用直接异常，而不是“未找到”。

### 🟠 C5. `chunkId` 未校验，可路径穿越

`beginChunk/readChunk` 直接 `join(chunksRoot, chunkId)`，没有走已有的 `chunkDir()` 校验。实测 `store.beginChunk('../../escape')` 能在 `videoDir` 之外创建 `escape.__staging`。
当前 job 计划只生成 6 位数字，风险有限；但这是可被调用方/未来 API 触碰的边界。

### 🟠 C6. 远程源 SSRF 白名单有洞

| 检查 | 结果 |
|---|---|
| `https://8.8.8.8/a.m4a`（裸公网 IP） | **放行**（`isIP` 分支只查私网，不查 CDN 后缀） |
| `maxDownloadBytes` | **未使用**，只检查输出文件 `maxTempBytes` |
| DNS rebinding | 未解析/固定 IP（报告已承认） |
| CRLF header / 私网 / localhost / 重定向 | ✅ 正确拒绝 |

### 🟠 C7. `index(execution:auto)` 不会自己取时长

工具只看调用方传的 `durationMs`（`video-index-tool.js:229-232`）。不传就永远走同步旧路径：
- B站 URL：不会下载媒体，通常只建 metadata/字幕，**内容没索引**；
- 本地长文件：会走旧 `index()`，长任务撞 15 分钟工具超时。
需要先 resolve 时长，或对 bilibili 默认 background。

### 🟡 其他

- **后台 job 不是独立进程**：`job-worker.js` 导出但没人用；实际是 `setImmediate` 在 DSH 同进程跑。DSH 重启后能 resume，但运行期间没有隔离（长任务与插件同生共死）。
- **capture_start 没有 region/URL 也返回 ok**（`region:null, pageUrl:null`），没有任何采集源。
- **`loopback-recorder.py --check` 需要先装 soundcard/pyaudiowpatch**；本机没有，抓播即使接线也不可用。
- `npm pack` 90 条目无法在本环境复核。

## 4. 建议修复顺序

1. **C1 抓播接线**（否则“抓播优先”不成立）
   - `captureStart` 里启动 `setInterval(session.tick, 1000)`；
   - 新增 Node `loopbackRecorder` 适配器（spawn `loopback-recorder.py --out ...`，stop 时收尾）；
   - 用 `spawnFrames` 抓 region 帧，按 chunk 落盘；
   - capture job 在 stop 后走 `runIndexingJob`（或边抓边提交）。
2. **C2 embedding 生产端**
   - engine 传 `returnEmbeddings:true`（可配）；
   - runner 输出 `speakerEmbeddings`（从 pyannote 的 embedding model 取）；
   - controller 在 finalize 时调 `mergeSpeakersByEmbedding`，写 mergeEvidence，未合并保持 provisional。
3. **C3 cancel 终态**
   - `jobCancel` 写 `cancelRequested`；`runIndexingJob` 在 await 后、commit 前检查 `aborted/cancelRequested`，禁止覆盖 cancelled。
4. **C4 jobId 容错**：工具层 try/catch，非法/不存在统一返回 `未找到/非法 jobId`。
5. **C5 chunkId 校验**：`beginChunk/readChunk/commitChunk` 全部走 `chunkDir()` 的 `^\d{6}$` 校验。
6. **C6 SSRF**：IP 字面量一律拒绝（CDN 不会用裸 IP）；`extractAudioRange` 用 `maxDownloadBytes`（Content-Length 或输出上限）。
7. **C7 auto 时长**：`index` 在 `auto` 时先 resolve 元数据（bilibili: `resolveStreams`；file: ffprobe/`durationMs` 参数），再决定 background。

## 2.3 仍存在的问题

### 1. `index(execution:"auto")` 仍不会自己取时长（唯一 harness fail）

工具只看调用方传入的 `durationMs`。不传就永远走同步旧路径：
- B站 URL 通常只建 metadata/字幕，**内容不索引**；
- 本地长文件可能撞 15 分钟工具超时。

README 已写明要传 `durationMs` 或用 `background`，所以这是“语义/易用性”问题，不是静默错误。建议 auto 时先 resolve 元数据（bilibili `resolveStreams` / file `probeMediaDurationMs`）再判定。

### 2. Speaker merge 需要额外的 gated 模型

启用 `speakerMerge:{enabled:true}` 后，runner 会另外加载 `pyannote/embedding`（**gated: auto**，10 个文件）。只装了 community-1 本地模型、没给 token/本地 embedding 模型时：

```
Could not download Model from pyannote/embedding.
pyannote inference failed: ...
```

整个 diarization 会失败，而不是“合并不可用但说话人照常”。默认关闭，所以不影响普通路径；但 README 只写了“speakerMerge 默认关闭”，没写还需要 `pyannote/embedding` 条款/`DSH_PYANNOTE_EMBEDDING_MODEL`。建议补文档，并让 embedding 失败时保留 diarization、只把 `speakerMerge` 标 `unavailable`。

### 3. 本机没有 loopback 后端

`loopback-recorder.py --check`：

```
{"ok": false, "detail": "no loopback backend; install soundcard or pyaudiowpatch"}
```

所以本机 `capture_start` 只能抓画面（`audioCapture: unavailable`），要“听到”得先 `pip install soundcard`。README 已提到这是可选依赖。

### 4. 真实抓播/CDP 仍未实测

capture 的 start→tick→chunk→query 是用 fake recorder/frame source/CDP 测的；真实屏幕抓帧、真实 WASAPI 环回、真实 Chrome CDP 还没跑过。建议用 30 秒 B站播放做一次 smoke。

### 5. 小项

- `captureStart` 要求 `region`，即使给了 URL 也一样（MVP 设计，可接受但可说明）。
- `.gitignore` 仍缺 `__pycache__/` / `*.pyc`（pack 靠 `.npmignore` 挡住了，git 提交前仍建议清）；`.venv-pyannote/` 已加入 ignore。
- 仍不是 git 仓库，未提交。

## 2.4 结论

**六项修复全部验证通过，抓播从“骨架”变成了“可注入测试的完整链路”**。剩下的不是回归，而是三个使用条件/文档问题：`auto` 不取时长、speaker merge 需要额外 gated 模型、本机缺 loopback 后端。真实抓播 smoke 仍是上线前最后一道没过的关。

## 5.5 仍存在的限制

- **抓播的 chapters 仍为 0**：ASR utterance 有了，但 capture bundle 没有做章节聚合。
